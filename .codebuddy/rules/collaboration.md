# AI 协作工程标准（项目层）

> 本文件承接全局规则（个人规则 `code.mdc` / `~/.codebuddy/CODEBUDDY.md` 第七章、第八章）下沉的工程标准，仅在本项目生效。
> 全局保留的行为约束（角色 / 优先级 / 工作流程 / 禁止事项 / 自主级别）不在此重复，避免双份维护漂移。

## 工具链约定（项目）

- **Python**：lint / format / import 排序统一使用 **Ruff** —— `ruff check` + `ruff format`。对应 Skill：`backend-patterns`。
- **前端**：`bun run typecheck` / `bun run lint` / `bun run test`。对应 Skill：`frontend-components`、`frontend-patterns`、`pureadmin-utils`。
- **验证命令以 `CODEBUDDY.md`「常用命令」章节为准**，本文件不重复列举。

## 快速交付原则

- 先跑通 MVP，再完善细节。
- 优先最短路径、最少依赖、可回滚方案。
- 不做过度抽象，不为未来假想需求设计。
- 但错误处理、基础安全、关键路径测试不能省。
- 小任务可自主完成；大任务必须先计划再执行。
- **优先级**：项目既有架构约定 > 本节快速交付原则。（框架选型、分层模式、Controller/Hook 等约定不得以「最短路径」为名绕过。）

## 代码标准

- 小函数、清晰命名、单一职责。
- 先正确，再简洁，最后才优化。
- 不写死配置、URL、密钥；使用环境变量或项目配置。
- 不复制粘贴大段重复逻辑；必要时提取，但不为抽象而抽象。
- 兼容项目锁定的语言/框架版本，不假设最新 API。
- 不修改 lock 文件（`uv.lock` / `bun.lock`），除非依赖变更且已确认。
- 不提交生成文件、缓存、构建产物，除非项目要求。

## 测试标准

- 核心逻辑、数据处理、边界条件必须有测试。
- Bug 修复优先加回归测试。
- UI / 脚本 / 一次性工具可手动验证，但要写清步骤。
- 测试要稳定、快速、可重复，不依赖网络和真实密钥。
- 不为了让测试通过而弱化断言或跳过测试。
- **测试夹具不得对共享引擎做破坏性 DDL**：后端 `conftest.py` 的共享 fixture 是全 session 复用的，删表类操作需用独立临时引擎（详见 `.codebuddy/memory/MEMORY.md` 测试基础设施一节）。

## 安全与权限

- 默认只读分析；写代码前确认允许修改范围。
- 不访问与任务无关的敏感文件。
- 不执行外部网络请求、安装全局包、修改系统配置，除非明确授权。
- 涉及用户输入、文件上传、数据库查询、命令执行时，必须考虑注入、越权、路径穿越、XSS/CSRF 等基础安全。
- 输出中如需展示敏感信息，必须脱敏。
- **密钥不入库**：`.env` 与数据库配置表中的 token / 密码不得写入代码、日志或提交记录。

## Git 与变更管理

- 不自动 commit/push，除非用户明确要求。（与全局规则一致：git 状态变更需显式授权，默认单次。）
- 提交要小、单一目的、语义化 message。
- 不 rebase/force push 共享分支。
- 不改无关文件；不清理他人代码。
- 回滚策略优先：能小步回退，不做不可逆操作。

## 沟通与输出

- 先结论，后细节；简洁、具体、可执行。
- 不确定就说不确定，不装懂；不写空话，不重复需求。
- 代码块标明语言和文件路径。
- 发现更好方案可以提，但不要擅自实施。
- 原有的两段式输出结构（[直接执行] + [深度交互]）与「喵~」语气规范（全局规则第一章）继续保留。
