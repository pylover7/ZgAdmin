## 1.2 AI 行为合约（每次对话必读）

- **定位**：AI = 资深软件工程师 + 结对程序员 + 代码审查者；用户 = 关键决策者、验收者、最终责任人。
- **自主级别**：默认 **L2**（可改代码，先给计划等确认）。触碰关键决策清单（架构、数据库 schema、公共 API、鉴权、支付、依赖引入、大重构、部署配置）**强制降回 L1**（只给片段）。
- **小任务客观判据**（须全部满足，任一不满足即降级为大任务 → 必须先计划、等确认再执行）：① 涉及文件数 ≤ 2；② 不触碰 `app/models/` 下任何文件的字段定义、不修改任何已注册路由的函数签名；③ 属关键决策清单之外；④ 验证命令执行时间 < 3 分钟且无需人工构造测试数据。
- **优先级**：项目既有架构约定 **>** 快速交付原则。
- **必守铁律**：不编造 / 不扩大范围 / 不隐瞒失败 / 不泄露秘密 / 不执行破坏性操作 / 关键决策先确认；验证命令必跑、交付五项（摘要、文件列表、验证结果、未验证与风险、下一步）必给；同问题最多试 2 次即停并求决策。
- **输出风格**：两段式（[直接执行] + [深度交互]，深度交互必须有实质内容）+ 每句结尾「喵~」。
- **Skill 机制**：`karpathy-guidelines` 始终第一个加载，其余按场景触发。

## 1.3 工作流协作规则

- **角色分工**：用户 = 关键决策者 + 验收者；AI = 实现者 + reviewer。
- **分析只读免授权**：读文件、搜索代码、运行只读验证命令（`ruff check` / `typecheck` / `pytest` 等）无需授权。
- **Git 状态变更**：`commit` / `push` / `merge` / `rebase` / `reset` / `checkout` / `stash` / `cherry-pick` / `revert` **不得自动执行**，需用户显式授权且默认单次。
- **Review 职责**：编码完成后 review（读码 + 只读验证 + 结构化报告）；修正建议只给片段，最终代码由用户自己改。
- **记忆库维护**：超 30 天的日志按主题蒸馏进本文件后删除；**本文件只收结论性陈述**（不写日期、不写叙事过程、不写易变数字）。

# 2. 项目概览

## 2.1 定位与技术栈

- **项目名**：ZgAdmin（后台管理系统模板）
- **技术栈**：后端 FastAPI + SQLModel + Alembic + uv（端口 7001）；前端 Vue 3 + vue-pure-admin + Element Plus + bun（端口 7000）

- **后端**：用户 / 角色 / 菜单 / 部门 / 通知 / 日志（登录·操作·系统）/ 配置表（SiteConfig / OAuthConfig / EmailConfig / SecurityPolicy）/ 文件管理。

- **前端**：vue-pure-admin v7 + Element Plus + Tailwind CSS 4。
- **表清单以代码为准**：`import app.models` 后读 `SQLModel.metadata.tables`。

# 3. 工程方法论

> 本节是**跨场景通用判据**，优先级高于第 4 节的具体教训。

## 3.1 局部观察 ≠ 全局结论（两个维度都必须声明覆盖范围）

**判据**：凡从局部观察推出的全局结论，**必须显式给出覆盖范围**。不声明范围的结论会被听者按自己的场景填满，而这个场景往往与实情不符。

### 空间维度：「单点实测」≠「整体验证」

- **反例**（引自参考项目）：只对 `user` 一张表跑了 `PRAGMA table_info`，就写下「**实测**：该库结构与模型一致」——实际 27 张表里有 2 张缺列。
- **危险点**：「实测」这个词**带着权威感，会让听者放弃二次怀疑**——**用验证的语气说未经验证的结论，比完全不验证更危险**。
- **正解**：全称判断（「A 与 B 一致」）**必须给出比对全集与命中数**（如「27 张表逐表比对，0 处差异」），**不能用单点抽查的动词去支撑全称结论**。

### 时间维度：「本次操作无破坏」≠「零风险」

- **反例**（引自参考项目）：把「不动现有数据」的方案描述为「**零风险**」，忽略了「**维持现状的代价**」——该库带着孤儿版本号与缺列，**不修它意味着后续任何迁移都无法在该库验证**。
- **错误本质**：把「本次操作不造成伤害」当成目标，而该问的是「**这个系统最终要处于什么状态**」。
- **正解**：评估方案风险时**必须把「维持现状的代价」计入**。「不动它」不是零风险，而是**延迟承担风险**。**不扩大范围 ≠ 不解决问题**。
- 附带自检：**描述与推荐冲突时，说明评估标准本身没想清**。

## 3.2 验证的适用范围必须显式标注

- **「测试全绿」只证明「在那个场景下没问题」，不证明「在你关心的场景下没问题」**。汇报验证结果时必须说清**场景**，否则「绿」这个信号会被默认放大。
- **判据**：看到「✅ 通过」时自问 **「这个绿，是在什么场景下绿的？」**；汇报与命名用**场景**而非**动作**——动作名（如「往返测试」）会诱导听者套用自己的场景，而两者可能完全不同。
- **推论**：验证环境与生产环境不同（如用「表已存在」的库验证迁移），会让错误静默通过——**验证路径必须与生产路径一致**。

## 3.3 破坏性操作必须附「破坏后的世界是什么样」

- 「重建 / 删除 / 迁移」类操作**为数不多且不可回退**（备份能救数据文件，救不回「重建后产生的新状态」）。交付物**必须包含「重建后状态说明」**，至少覆盖：
  - **DB 数据**：清空了哪些（是否需重走 `/init`）
  - **磁盘数据**：`static/` 上传文件等是否保留
  - **孤儿状态**：DB 无记录但磁盘仍存在的目录清单
  - **外部依赖**：Redis key / 备份仓库是否受影响
  - **用户须手动做的事**：清单
- **理由**：**边界必须与结论并置，不能靠用户自己推断**。**「重建成功」不等于「用户知道接下来该做什么」**。

## 3.4 状态残留与排查范式

- **模块级缓存的「代次」机制**：同一测试内多轮循环时必须**逐轮重置代次**，否则首轮成功后早退分支命中，表现为「不发请求却返回成功状态」。夹具须同步重置所有新增的模块级状态。
- **排查范式**：独立脚本复现通过但 pytest 内失败 → 写临时探针 test 用 `pytest -s` 打印**每轮真值**，比反复读代码快得多。
- **判断失败是否由自己所致**：按文件名归类失败用例——若集中在与被改模块无关的文件、且错误信息指向同一对象，即为**测试污染**而非真实回归。

## 3.5 规则要抓精神不要抓字面

- 「慎用 try/except」的**上位原则是「慎用一切绕过手段」**，noqa / `@ts-ignore` / `eslint-disable` / skip 都是同类。
- **lint 报错是信号不是麻烦**，加 noqa 是把问题藏起来，不是解决问题。
- **拒绝经验主义**：不能因为「之前有 noqa」就认为「该有 noqa」。
- **对用户决定的「反述」必须以原话为准**：**依赖「自己对上一轮对话的摘要」去做论证是危险源**；反述用户决定前必须回读原话。

## 3.6 结论时效性检查

- **判断「某结论是否过期」的最快手段是 `git log`**：比通读代码更快发现「最近一次提交已推翻该结论」。
- **静态清单（盘点报告）必然腐化，必须标注快照日期**：其保质期取决于下一次字段增删。**写盘点类文档必须标日期**，否则后来者会按过期结论行动。
- **issue 描述会过期，处理前必须复现**：issue 里写的现象是「历史时点的现场」，可能已被别的改动悄悄修好。**读描述就动手会做无用功**。

# 4. 具体技术教训

## 4.1 数据库与迁移

- **`create_all` + `stamp` 模式：已存在表升级后不自动加列**：`create_all` 只建不存在的表，`stamp` 只标版本号不跑迁移 → 已有数据的环境升级新字段不会自动加。**判据：加字段后必须用 `PRAGMA table_info` 校验列是否真加上，不要只看版本号。**
- 本项目当前即处于该模式（详见 `.codebuddy/rules/backend-architecture.md`「数据模型变更铁律」的现状与待办）。
- SQLite 不支持 `DROP COLUMN`，需 `batch_alter_table(...)` 重建表；加 `NOT NULL` 列需 `server_default`。
- `alembic history` 的输出折行会产生「多头」假象，**判断分支数必须用 `alembic heads`**。
- 降级时若表结构不一致，手动改 `alembic_version` 回退版本号再 upgrade（**仅限临时库，开发库走重建流程**）。

## 4.2 SQLModel / SQLAlchemy

- **mixin 里禁止直接 `sa_column=Column(...)`**（Column 实例被所有子类共享，报 already assigned）；正解用 `sa_column_kwargs`。
- **UUID 列绑定参数禁止 `str()`**：路由把 `str(id)` 传给 GUID 列比较会撞绑定处理器 → 500；controller 方法签名注解也要用 UUID 保持一致。
- **`Field()` 不支持 pydantic v2 的 `pattern` 参数**；正解用 `Annotated[str, StringConstraints(pattern=r"...")]` 定义类型别名。
- 表模型**不做类型转换**：`table=True` 的构造函数不转换类型，datetime 字段传 ISO 字符串会在 flush 时炸。
- **删除模型时须核实**：`models/__init__.py` 是否有该模块的 import 行决定它是否被注册；**删除时须同步清理引用它的配置**，否则留下引用不存在文件的死配置。
- **「import 即副作用」毒化是全局的**：SQLAlchemy mapper 配置是全局延迟一次性的，一旦触发即波及所有依赖 ORM 的测试，而**单文件跑全绿**——回归必须全量跑。

## 4.3 FastAPI 与响应契约

- FastAPI 路由函数必须有显式 `return Success(...)`，返回 None 会被转成非 200。
- `Success` / `SuccessExtra` 是 starlette `Response` 子类，直接调用端点函数时需 `json.loads(resp.body)`，**不能**访问 `.success` / `.code` / `.data` 属性。
- `DependUser` 在缺 `Authorization` 头时 FastAPI 先做参数校验 → **422**（不是 401）；非法 token 才返回 401。
- **JWT access / refresh 靠 payload 的 `token_type` 字段区分**，校验不匹配 401。

## 4.4 日志

- **`dictConfig` 里 `loggers` 引用的 handler 名必须在 `handlers` 中声明**，否则 `Unable to add handler 'xxx'`。
- **模块被包级同名变量遮蔽时，`dictConfig` 的 `"()"` 字符串路径会失败**：包 `__init__.py` 末尾若有与子模块同名的赋值，`getattr` 会命中类而非模块。正解：指向未被遮蔽的模块，或直接传类对象。**同类风险**：任何「包 `__init__` 里有与子模块同名的包级变量」都会踩。
- **后台 asyncio task 入口必须有 try/except 兜底**（网络 I/O 异常无法用条件判断避免），否则报 `Task exception was never retrieved`。这与「慎用 try/except」不冲突——后者针对的是**流程控制**用途。
- `psutil.cpu_percent(interval=None)` 必须**复用同一 Process 对象**（新建对象每次都是无基线的首次调用，恒为 0）。
- `httpx` 流式下载 `AsyncClient` 必须 `follow_redirects=True`。

## 4.5 前端

- **`useRenderIcon` 必须传图标组件，不能传字符串**：`import Search from "~icons/ri/search-line"` + `:icon="useRenderIcon(Search)"`。
- **`fail` 响应体是 `{code, msg, data}`，判断用 `code` 更稳**；axios 拦截器对 400 做特殊处理（resolve），业务层判 `success` 会取到 `undefined`。
- **`@pureadmin/table`：`formatter` 第一个参数就是 row 本身**（直接解构），`cellRenderer` 才收 `{ row }`。
- `el-dialog` **无 height 属性**（height prop 是布尔 fullscreen）；`modal-class` 全局样式会命中所有 dialog overlay，不能用。
- `el-popconfirm` 的 `#reference` slot 内 `v-if` 会空 slot 报 `ElOnlyChild`，`v-if` 应放在 `el-popconfirm` 上。
- **`el-select` 的 `model-value` 不在 options 中会回退显示原始值**而非 placeholder；规避：options 未加载时不渲染 el-select。
- **非代码资源文件（YAML / JSON / 配置）改了之后，必须用「解析它 / 构建它」的方式验证**：typecheck / eslint / vitest 都**不解析** locale YAML 语法，三项全绿也可能是坏的——只有 `bun run build` 或独立解析脚本能发现。**别把「工具没报错」当成「文件没问题」。**
- ReDialog 表单：`beforeSure` 必须经子组件 `defineExpose` 的 `getFormData()` 读实时数据，不能读 dialog 创建时的 props 快照。

## 4.6 测试基础设施

- **后端测试**：`cd backend && uv run pytest`。当前 `pyproject.toml` **未设置 `asyncio_mode`**（async 测试需自行确认运行方式）与 **`fail_under` 覆盖率门槛**。
- **前端测试**：`cd frontend && bun run test`。
- **⚠️ `conftest.py` 的共享 fixture 是 session 级的**：任何测试都**不得**对其做破坏性 DDL（删表等）。需要真实改结构的测试用独立临时引擎（`create_engine("sqlite:///:memory:")`），不要 patch 共享引擎。
- **跨模块 / 跨会话污染时，单文件全绿不代表安全**：必须全量跑（SQLAlchemy mapper 配置、session 级引擎等均为全局状态）。
- **测试夹具撞 UUID 的坑**：fixture 若用 `uuid4()` 造目录名而 DB 记录用独立生成 id，两者不相等——凡直写按 DB id 拼的路径前必须 `mkdir`。
- **mock 约定**：① 函数内 from-import 必须 patch **源模块**属性（patch 使用方命名空间无效）；② `with obj as x` 的 mock 需 `__enter__.return_value = obj` 自指；③ async 函数的测试要 `async def`，同步测试拿到 coroutine 必挂；④ mock asyncio 原语时 side_effect 必须消费已创建的实参协程（`coro.close()`），否则 GC 报 RuntimeWarning 且挂在无关测试上。
- **pydantic 只读 property 不可 setattr 实例**：patch 须走类级替换。

## 4.7 安全

- **`SECRET_KEY` 生产环境必须修改**；管理员密码首次启动自动生成并打印到控制台。
- **上传 / 文件路径操作必须做路径穿越防护**：解析后强制校验目标仍在允许目录内；用户可控的 id / 文件名必须走白名单校验。
- **敏感操作需二次确认 + 操作日志**。
- **密钥不入代码仓库**：`.env` 与数据库配置表中的 token / 密码不得写入代码、日志或提交记录。
